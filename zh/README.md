# Agent Kit（中文参考译本）

> 参考译文，**英文版 `../README.md` 为准**。本目录文件不参与复制、不会被 agent 读取。

一份写清仓库事实的文件，加四段提示词。Copilot、Claude Code、Cursor、Codex，以及任何会读
`AGENTS.md` 的工具都能用。没有脚本，没有安装步骤，没有要执行的东西。

## 你能得到什么

agent 不再发明目录、不再猜测试命令、不再悄悄改你不让它碰的文件。全部承诺就这些。
它不会让设计变得更好。

## 包含什么

```
templates/AGENTS.md   复制到仓库根目录，改名 AGENTS.md —— 唯一的产物
README.md             说明：怎么填、四段提示词、强制约束放哪
zh/                   中文参考译本
```

## 怎么用

1. **复制** `templates/AGENTS.md` 到仓库根目录。
   已经有 `AGENTS.md` 了？**合并，绝不替换。** 补上缺的块，保留你的原文措辞，删掉重复表述。
   已有文件可能被其他工具加载，也可能记着代码里看不出来的决定。
2. **用下面的提示词 1 打出事实草稿**，贴进文件。
3. **两节必须自己写**：架构不变量、禁止事项。任何工具都推不出来，而且写错比不写更糟——
   agent 把这份文件当权威。
4. **每条命令先跑一遍**再留下。从配置文件里抄来的候选命令，跑不通的比例相当高。
5. **确认它真被加载了。** 问一句“这个仓库跑测试用什么命令”，展开回答的引用列表，
   看有没有 `AGENTS.md`。文件存在不等于被读过。

## 四段提示词

按顺序用，在同一个对话里。只读规划和只读审查由提示词保证，不依赖具体工具，所以到处可用。

**1 — 摸事实，只读**

```
只读。读 package.json / Makefile / CI 配置 / 依赖清单和目录结构。报告：技术栈与版本、
包管理器（多个锁文件并存要警告）、安装/构建/测试/lint 的候选命令、生成目录或第三方目录、
目录地图（每个目录挑一个写得最规范的文件作范例）。无法确定的就写 "none found"。
绝不编造命令。
```

**2 — 出方案，只读**

```
只读。先读 AGENTS.md，再读你要动的代码。
需求：<改什么、改哪里、怎样算做完、怎么验证>。
按顺序列出要改的文件和理由，以及确切的验证命令。你引用的每个路径都必须真实存在。
如果 AGENTS.md 还是未填的模板，明说，并把其余内容标注为推断。
```

**3 — 实施**

```
严格实施上面的方案，不多做。按 AGENTS.md 决定代码位置和分层。
不加依赖，不改测试来让检查通过，不顺手重排无关代码。
运行 AGENTS.md 里的验证命令并贴出输出。
```

**4 — 审查，只读**

```
只读。对照 AGENTS.md 审查这次改动：越界修改、被削弱或删除的测试、违反分层、
声称跑了但实际没跑的验证。按严重度列出问题，带 file:line。不要夸奖，不要复述改动内容。
```

## 必须成立的规矩，交给 linter

文字是建议，linter 是闸门。`Architecture invariants` 里凡是能机械检查的，就应该真的机械检查：

| 语言 | 工具 |
| --- | --- |
| JS / TS | dependency-cruiser：`no-circular`、`not-to-unresolvable`、自定义分层规则 |
| Python | import-linter |
| Java / Kotlin | ArchUnit |
| Go | `internal/` 包，编译器直接强制 |

用 dependency-cruiser 时不要把 `node_modules` 写进 `exclude`——那会让依赖类规则静默失效。
改用 `doNotFollow`。

## 局限

- `AGENTS.md` 是建议，模型可以不理会；只有 CI 能让规矩真正绑住。
- 效果上限由你手写的那两节决定。
- 规划、审查和写代码用的是同一个模型，自评偏差依然存在。
- 命令变了而文件没跟着变，它就会腐烂。命令变了就重跑提示词 1，
  并保留“改动必须同 diff 更新本文件”那条规矩。
